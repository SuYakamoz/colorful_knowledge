# 《多彩知识宝盒》技术教程(学习教材)

> 讲师:特级讲师 · 课程对象:AI 应用入门学习者
> 课程定位:以一个真实运行的项目为案例,讲透"AI 内容生成 + 消息推送 + 数据积累"的完整工程

---

## 一、整体介绍

### 1.1 这个项目是什么

一个**每天自动推送 3 条常识到微信**的系统:AI 每天现场生成内容 → 企业微信官方 API 发卡片 → 个人微信接收 → 内容自动积累,以后还能做网站。

**一句话**:它是"内容工厂(生成)+ 快递(推送)+ 仓库(积累)"三合一的自动化流水线。

### 1.2 架构四环节(记住这张图)

```
① 生成:DeepSeek AI 按设定角色生成 3 条不同领域常识
        (失败自动回退本地知识库,保证不断更)
② 推送:企业微信官方 API(gettoken → 发 textcard 卡片)
        → 个人微信(微信插件)
③ 展示:点卡片"查看详情" → 服务器详情页(白名单安全服务)
④ 积累:每天内容追加进 data/common_sense.jsonl(网站数据源)
```

### 1.3 为什么这么设计(三个关键取舍)

| 设计 | 为什么 |
|------|--------|
| AI 生成 + 知识库兜底 | AI 内容天天新鲜;知识库保证 AI 挂掉也不断更 |
| 企业微信而非个人号机器人 | 微信官方规则:只有企业微信提供"主动推送"API;个人号机器人会封号 |
| 同一天幂等(只存第一条) | 防手动测试+定时重复积累脏数据 |

## 四、详细讲解

### 4.1 AI 生成与知识库兜底(push_daily.py 核心)

```python
if use_ai:
    try:
        items = generate_by_ai()      # ① 调 DeepSeek 生成
        source = "ai"
    except Exception as e:
        items = pick_daily_items()    # ② 失败 → 知识库随机抽
        source = "fallback"
```

**双保险思想**:主通道(AI)挂了,备用通道(知识库)顶上,推送永不断。类比:飞机双引擎。

**易错点**:AI 返回的 JSON 要严格解析(`json.loads`),模型偶尔返回多余文字会解析失败 → 所以用 `response_format: json_object` 强制 JSON。

### 4.2 配置集中(config.py)

所有可调项(条数/模型/角色 prompt/通道/卡片类型)集中在 `config.py`,密钥放 `.env`(已被 gitignore,不会传 GitHub)。

**设计思想**:改配置 = 改一个文件,不用翻代码。类比:电器的控制面板 vs 拆开改电路。

**易错点**:`.env` 支持行内注释(`KEY=值 # 注释`),加载器会自动剥离——避免密钥被注释污染。

### 4.3 幂等设计(防重复积累)

```python
if today in existing_dates:   # 今天已存过?
    print("跳过落盘(幂等)")
    return
```

**为什么**:每天定时推一次 + 可能手动测试多次,如果不幂等,同一天会存好几份,污染网站数据。

**易错点**:幂等只查"日期",所以**每天只保留第一条**;想看当天最新内容,点卡片看详情(不落盘的内容不展示在列表,但卡片有)。

### 4.4 企业微信推送(官方 API)

```
① GET gettoken?corpid=企业ID&corpsecret=Secret → access_token
② POST message/send?access_token=token
   {"touser": "@all", "msgtype": "textcard",
    "agentid": 你的AgentId,   # 示例:填应用详情里的 AgentId(数字)
    "textcard": {"title": ..., "description": ..., "url": ...}}
```

**两步走**:先拿令牌,再发消息。

**可信IP 前置**:企业微信要求服务器 IP 加白名单(「企业可信IP」),否则报 `60020`。配置前还要先通过「接收消息服务器URL」验证(需要一个公网 URL 响应验证——我们用服务器部署的 `verify_server.py`)。

**易错点**:textcard 的 description **上限 512 字节**(中文 1 字≈3 字节,约 170 字),所以卡片放不下 3 条全文 → 设计为"卡片摘要 + 点击看详情页"。

### 4.5 详情页与白名单安全

**为什么不能裸用 http.server**:它把整个目录暴露(含 `.env` 密钥!),谁都能下载。

**白名单服务**(`server/serve_web.py`):只允许 `index.html` / `data` / `assets/logo.png`,其他一律 403。

```python
ALLOWED = {"/": "index.html", "/data/common_sense.jsonl": ..., ...}
if path in ALLOWED: ...正常响应...
else: ...403 Forbidden...
```

**易错点**:Python 的 `b"中文"` 字节字面量**不能含非 ASCII**——403 响应体要 `.encode("utf-8")` 而不是 `b"..."`。

### 4.6 农历模块(零依赖的小而美)

**需求**:推送里带农历日期/干支/节气/节日。为什么不用 `lunar_python` 库或在线 API?

| 方案 | 问题 |
|------|------|
| 在线 API | 要钱/限流/依赖外部服务,网络挂了就没农历 |
| lunar_python 库 | 服务器要 pip 装包,破坏"零依赖"底线 |
| **内置 lunar.py** | 农历本质是"查表":1900-2100 一张数据表 + 闰月算法,内置即可 |

**核心思想**:农历转换 = 数据表(201 项)+ 位运算解码 + 闰月处理;**节气**用经典 sTermInfo 分钟偏移表;**节日**用农历月日匹配。整个模块零依赖、离线可用。

**易错点**(开发时踩过的坑):①闰月天数可能是 29 或 30,不能一律 30;②闰月后月份序号会偏移,要用"真实月号"算法;③节气近似公式会偏差 1 天,要用 sTermInfo 查表法。

### 4.7 服务器部署三件套

| 工具 | 角色 | 类比 |
|------|------|------|
| **cron** | 每天 08:00 定时执行推送 | 闹钟 |
| **systemd** | 守护详情页服务,开机自启、崩溃自拉 | 保安 |
| **git pull**(cron 里) | 每天自动同步最新代码 | 自动更新 |

**更新流程**:本地改 → `git push` → 服务器次日 8 点自动 pull + 推送;想立即生效跑 `bash server/deploy.sh`。

## 五、运行过程(一次推送的完整追踪)

```
08:00 cron 触发
  → git pull origin main(同步最新代码)
  → python3 push_daily.py
      → config.py 读配置(模型/密钥/通道)
      → 调 DeepSeek 生成 3 条(领域各不相同)
      → 幂等检查:今天存过?跳过 / 没存过?写入 jsonl
      → 企业微信 gettoken → 发 textcard 卡片
      → 响应 errcode:0 = 成功
  → 你微信收到卡片 → 点查看详情 → 详情页(index.html 读 jsonl 渲染)
```

## 六、总结

### 6.1 一句话心法

**内容要"活"(AI 生成)、通道要"稳"(官方 API)、数据要"攒"(落盘积累)、服务要"安全"(白名单)**——一个"小而完整"的 AI 应用就该这样。

### 6.2 易错点总表

| # | 易错点 | 后果 |
|---|--------|------|
| 1 | AI 返回 JSON 解析失败 | 走知识库兜底(能忍,但内容变旧) |
| 2 | `.env` 值带注释不清理 | URL 含空格报错 |
| 3 | 卡片用 markdown | 个人微信显示"暂不支持此消息类型" |
| 4 | textcard 超 512 字节 | 卡片内容被截断 |
| 5 | 裸用 http.server 当详情页 | `.env` 密钥可被下载 |
| 6 | `b"中文"` 字节字面量 | 语法错误 |
| 7 | 可信IP 没配 | 推送报 60020 |
| 8 | 幂等想当然 | 数据重复污染网站源 |

### 6.3 自测题答案

1. **不会断**:AI 失败自动回退知识库(`try/except` 双保险),保证每天都有推送。
2. **只存 1 条**:幂等按日期去重,同一天第一次落盘后,后续跳过。
3. **微信插件不支持 markdown**:textcard 是个人微信能显示的卡片类型;markdown 仅企业微信 App 内显示。
4. **IP 不在白名单**:「企业可信IP」加上服务器公网 IP(先配好接收消息URL 验证)。
5. **目录泄露**:http.server 把 `.env`、`config.py` 全部暴露可下载;白名单服务只放行网页文件,其余 403。
